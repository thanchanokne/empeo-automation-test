# empeo Registration Automation Testing (การทดสอบระบบลงทะเบียน empeo อัตโนมัติ)

## ภาพรวมของโปรเจกต์ (Project Overview)
โปรเจกต์นี้จัดทำขึ้นเพื่อทดสอบฟังก์ชันการทำงานของระบบลงทะเบียน empeo บนสภาพแวดล้อม UAT แบบอัตโนมัติ สำหรับส่งแบบทดสอบตำแหน่ง Automation Tester โดยครอบคลุมกระบวนการลงทะเบียน (Happy Path), การตรวจสอบความถูกต้องของข้อมูลที่กรอก (Form Validation), การทำงานของโค้ดส่วนลด (Promo Code) และการตรวจสอบหน้ายืนยันรหัส OTP

- **ระบบเป้าหมาย**: empeo Registration (UAT)
- **URL เป้าหมาย**: https://portal.uat.gofive.co.th/Register/empeo

---

## เทคโนโลยีที่ใช้ (Tech Stack)
- **Python** (ภาษาที่ใช้ในการพัฒนาชุดทดสอบ)
- **Playwright** (เครื่องมือสำหรับทำ Browser Automation)
- **pytest** (Test Framework สำหรับจัดการและรันชุดทดสอบ)
- **pytest-playwright** (ปลั๊กอินสำหรับเชื่อมต่อ pytest เข้ากับ Playwright)

## โครงสร้างโปรเจกต์ (Project Structure)

```text
empeo-automation-test/
│
├── tests/
│   ├── test_registration.py   # ทดสอบกระบวนการลงทะเบียนที่ถูกต้อง (Happy Path) จนถึงหน้า OTP
│   ├── test_validation.py     # ทดสอบการตรวจสอบฟิลด์บังคับและรูปแบบข้อมูล (Validation)
│   ├── test_promo.py          # ทดสอบการใช้งานโค้ดส่วนลดทั้งกรณีที่ถูกต้องและไม่ถูกต้อง
│   └── test_otp.py            # ทดสอบกรณี Negative ของการยืนยันรหัส OTP
│
├── requirements.txt           # รายการแพ็กเกจที่จำเป็นสำหรับโปรเจกต์
├── pytest.ini                 # ไฟล์ตั้งค่าการทำงานของ pytest
├── .gitignore                 # กำหนดไฟล์และโฟลเดอร์ที่ไม่ต้องการบันทึกเข้า Git
└── README.md                  # เอกสารอธิบายโปรเจกต์และรายงานผลการทดสอบ
```

### รายละเอียดของไฟล์สำคัญ:
- **`tests/test_registration.py`**: ทดสอบโฟลว์การลงทะเบียนกรณีข้อมูลถูกต้องทั้งหมด (ค้นหาบริษัท, เลือกประเภทธุรกิจ, เลือกจำนวนผู้ใช้งาน, กรอกชื่อ-นามสกุล, อีเมล, เบอร์โทรศัพท์ และยอมรับเงื่อนไข) จนกระทั่งหน้าต่างยืนยัน OTP ปรากฏขึ้นมา
- **`tests/test_validation.py`**: ตรวจสอบข้อความแจ้งเตือนเมื่อไม่กรอกข้อมูลในช่องที่จำเป็น (บริษัท, ประเภทธุรกิจ, จำนวนผู้ใช้งาน, อีเมล, ชื่อ, นามสกุล, เบอร์โทรศัพท์) รวมถึงการตรวจสอบรูปแบบอีเมล, ความยาวของเบอร์โทรศัพท์ และการไม่ยอมรับเงื่อนไข
- **`tests/test_promo.py`**: ตรวจสอบการใช้งานรหัสส่วนลด ทั้งโค้ดที่มีในระบบและโค้ดที่ไม่มีในระบบ
- **`tests/test_otp.py`**: ตรวจสอบพฤติกรรมของหน้าต่างยืนยัน OTP ในกรณี Negative เช่น ไม่กรอก OTP, กรอกไม่ครบ 6 หลัก และกรอก OTP ผิด
- **`pytest.ini`**: กำหนดโฟลเดอร์รันเทส (`tests`), รันบน Chromium เป็นค่าเริ่มต้น และเปิดแสดงผลลัพธ์แบบละเอียด (`-v`)
- **`requirements.txt`**: ระบุเฉพาะ Library ที่จำเป็น ได้แก่ `playwright`, `pytest`, `pytest-playwright`

## ขอบเขตการทดสอบ (Test Coverage)

### 1. การลงทะเบียน (Registration)
- **การส่งแบบฟอร์มลงทะเบียนที่ถูกต้องจนถึงหน้ายืนยัน OTP**: กรอกข้อมูลครบถ้วน ถูกต้องตามเงื่อนไข ส่งแบบฟอร์ม และตรวจสอบว่าระบบเปิดหน้าต่างยืนยัน OTP สำเร็จ

### 2. การตรวจสอบความถูกต้องของข้อมูล (Validation)
- **บังคับกรอกบริษัท (Required company)**: ตรวจสอบข้อความเตือนเมื่อไม่กรอกเลขผู้เสียภาษีหรือชื่อบริษัท
- **บังคับเลือกประเภทธุรกิจ (Required business type)**: ตรวจสอบข้อความเตือนเมื่อไม่เลือกประเภทธุรกิจ
- **บังคับเลือกจำนวนผู้ใช้งาน (Required number of users)**: ตรวจสอบข้อความเตือนเมื่อไม่เลือกจำนวนผู้ใช้งาน
- **บังคับกรอกอีเมล (Required email)**: ตรวจสอบข้อความเตือนเมื่อไม่กรอกอีเมล
- **บังคับกรอกชื่อ (Required first name)**: ตรวจสอบข้อความเตือนเมื่อไม่กรอกชื่อ
- **บังคับกรอกนามสกุล (Required last name)**: ตรวจสอบข้อความเตือนเมื่อไม่กรอกนามสกุล
- **บังคับกรอกเบอร์โทรศัพท์ (Required phone)**: ตรวจสอบข้อความเตือนเมื่อไม่กรอกเบอร์มือถือ
- **รูปแบบอีเมลไม่ถูกต้อง (Invalid email)**: ตรวจสอบข้อความเตือนเมื่อกรอกอีเมลผิดรูปแบบ
- **เบอร์โทรศัพท์สั้นเกินไป (Invalid/short phone)**: ตรวจสอบข้อความเตือนเมื่อกรอกเบอร์มือถือน้อยกว่าจำนวนที่กำหนด
- **เบอร์โทรศัพท์ยาวเกินไป (Invalid/long phone)**: ตรวจสอบข้อความเตือนเมื่อกรอกเบอร์มือถือเกินจำนวนที่กำหนด
- **ไม่ยอมรับข้อกำหนดและเงื่อนไข (Terms & Conditions validation)**: ตรวจสอบว่า Checkbox ไม่ถูกเลือกเมื่อผู้ใช้ไม่ได้กดยอมรับเงื่อนไข

### 3. โค้ดส่วนลด (Promo Code)
- **โค้ดส่วนลดที่ถูกต้อง (Valid promo: FREE15DAY)**: ตรวจสอบว่าระบบยอมรับโค้ดและโค้ดยังคงปรากฏอยู่ในช่องหลังกดใช้งาน
- **การตรวจสอบโค้ดส่วนลดที่ไม่ถูกต้อง (Invalid promo validation)**: ตรวจสอบว่าระบบปฏิเสธโค้ดส่วนลดที่ไม่มีอยู่ในระบบ (`Banana`)

### 4. รหัส OTP (OTP)
- **ไม่กรอก OTP (Empty OTP)**: ตรวจสอบว่าปุ่มยืนยันอยู่ในสถานะปิดการใช้งาน (Disabled)
- **กรอก OTP ไม่ครบ 6 หลัก (Incomplete OTP)**: ตรวจสอบว่าปุ่มยืนยันยังคงปิดการใช้งาน (Disabled)
- **กรอก OTP ไม่ถูกต้อง (Invalid OTP)**: ตรวจสอบว่าเมื่อกรอกรหัสผิด (`654123`) ระบบไม่อนุญาตให้ผ่านและยังคงอยู่ที่หน้าต่าง OTP
- **การทดสอบกรอก OTP ที่ถูกต้องด้วยข้อมูลที่ได้รับ (Valid OTP flow attempted with provided test data)**: ทำการทดสอบโฟลว์การกรอก OTP `123456` ตามข้อมูลที่ได้รับ (ดูรายละเอียดในหัวข้อ Known Issues)

## ผลการทดสอบและประเด็นที่พบ (Test Results / Known Issues)

### 1. พฤติกรรมของโค้ดส่วนลดที่ไม่ถูกต้อง (`test_invalid_promo_code`)
- **ผลลัพธ์ที่คาดหวัง (Expected)**: ระบบควรปฏิเสธรหัสส่วนลดที่ไม่ถูกต้องหรือไม่มีในระบบ (เช่น `Banana`) และแสดงข้อความแจ้งเตือนข้อผิดพลาด เช่น `"ไม่พบรหัสส่วนลด"`
- **ผลลัพธ์จริงที่พบ (Observed)**: ระบบ UAT ไม่แสดงข้อความแจ้งเตือนข้อผิดพลาดตามที่คาดหวัง และดูเหมือนจะยอมรับรหัสส่วนลดใดๆ ที่กรอกเข้าไป
- **การจัดการ**: เคสทดสอบนี้คงค่า Assertion เดิมไว้และ**จงใจปล่อยให้ FAIL** เพื่อแสดงให้เห็นถึง Defect หรือข้อผิดพลาดที่เกิดขึ้นจริงของระบบ UAT โดยไม่แก้ไขผลที่คาดหวังเพื่อให้เทสผ่าน

### 2. พฤติกรรมการทดสอบ OTP 123456 แบบอัตโนมัติ (OTP 123456 automation behavior)
- **ข้อมูลทดสอบ**: รหัส OTP สำหรับสภาพแวดล้อม UAT คือ `123456`
- **การทดสอบด้วยมือ (Manual Testing)**: การทดสอบแบบ Manual ก่อนหน้านี้สามารถใช้รหัส `123456` ผ่านไปยังหน้าตั้งรหัสผ่านได้สำเร็จ
- **การทดสอบอัตโนมัติ (Playwright Automation)**: ในระหว่างการรันเทสอัตโนมัติ ระบบ UAT ปฏิเสธหรือไม่ยอมรับรหัส OTP `123456` แม้ว่าช่องกรอก OTP ทั้ง 6 ช่องจะมีค่าตัวเลขถูกต้องครบถ้วน
- **ข้อสรุป**: ประเด็นนี้เกี่ยวข้องกับสถานะของระบบ UAT, การจัดการ Session หรือกลไกการตรวจสอบ OTP ของระบบภายนอก ตามหลักการทดสอบที่ดี เราจะไม่เขียนโค้ดเพื่อหลบเลี่ยงหรือจำลองผลลัพธ์ว่าผ่าน (No fake verification) จึงบันทึกประเด็นนี้ไว้เป็นข้อจำกัดของสภาพแวดล้อม UAT

### 3. การทดสอบการตั้งรหัสผ่าน (Password tests)
- การทดสอบการตั้งรหัสผ่าน (Password validation) จำเป็นต้องผ่านขั้นตอนการยืนยันรหัส OTP ให้สำเร็จก่อน
- เนื่องจากขั้นตอนการยืนยัน OTP แบบอัตโนมัติยังไม่สามารถผ่านได้อย่างเสถียรบนระบบ UAT การทดสอบส่วนการตั้งรหัสผ่านจึงถูกบันทึกไว้ในเอกสาร Test Case Design แต่ยังไม่ได้นำมาทำเป็น Automated Test ในชุดทดสอบนี้ เพื่อป้องกันไม่ให้เกิดผลลัพธ์ที่ Flaky หรือ Fail โดยไม่จำเป็น

## ข้อสังเกตเพิ่มเติม (Notes)
- **สภาพแวดล้อม UAT**: การทดสอบนี้ทำงานบนสภาพแวดล้อมทดสอบจริง (UAT) ซึ่งอาจมีความล่าช้าของเครือข่ายหรือสถานะข้อมูลที่เปลี่ยนแปลงได้
- **ความขึ้นตรงต่อข้อมูลและสภาพแวดล้อม**: พฤติกรรมบางอย่างอาจขึ้นอยู่กับสถานะของข้อมูลทดสอบในระบบ UAT ณ ขณะนั้น
- **หลักความถูกต้องของการทดสอบ (Test Integrity)**: ในงาน Automation Testing การที่เทสเคสมีสถานะ Fail ไม่ได้แปลว่าโค้ด Automation เขียนผิดพลาดเสมอไป แต่เป็นการทำหน้าที่สะท้อนให้เห็นว่าพฤติกรรมจริงของแอปพลิเคชันไม่ตรงกับผลลัพธ์ที่คาดหวังตามข้อกำหนด (Requirements)
